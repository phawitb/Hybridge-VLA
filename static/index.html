1. System Overview

Hybridge VLA is a Vision-Language-Action system that converts natural language instructions into structured robotic execution plans. It uses Google Gemini VLM models to analyze images and generate step-by-step plans with bounding box coordinates for a single-arm robot with one gripper.

The system provides:

  • A web UI to test Gemini API with custom instructions, methods, and images
  • Automatic prompt generation from a configurable template
  • Plan visualization with bounding boxes overlaid on images
  • Result storage and historical review

4. Configuration (config.yaml)

All settings are centralized in config.yaml. The server reloads this file on every request, so changes take effect immediately without restart.

4.1 Gemini Settings

gemini:
  api_key: "AIzaSy..."    # Your Gemini API key
  default_model: "gemini-2.5-flash-lite"

4.2 Models

Each model entry defines id, name, group (for dropdown grouping), and input_limit (max input tokens for the usage bar).

models:
  - id: "gemini-2.5-flash-lite"
    name: "Gemini 2.5 Flash-Lite"
    group: "Gemini 2.5"
    input_limit: 1048576

4.3 Available Methods

The list of valid method_id values for the robot. Displayed as editable chips in the UI and injected into the prompt via {available_methods}.

available_methods:
  - ik_reach_object_v1
  - act_gripper_grasp_v1
  - act_gripper_release_v1
  - act_drawer_open_v1
  - act_drawer_close_v1
  - act_door_open_v1
  - act_door_close_v1

4.4 Prompt Template

Uses two placeholders replaced at runtime by the frontend:

  • {instruction} — the user's natural language instruction
  • {available_methods} — bullet list of methods
prompt_template: |
  You are a robotic task planner for a VLA system.
  ...
  ## Input
  {instruction}
  ...
  ## Available Methods
  {available_methods}
  ...

4.5 Storage

storage:
  results_dir: "data/results"   # JSON result files
  images_dir: "data/images"     # Uploaded images

5. API Reference

5.1 GET /api/config

Returns application configuration (models, default model, methods, prompt template). API key is NOT exposed.

Response:

{
  "models": [
    {"id": "gemini-2.5-flash-lite", "name": "Gemini 2.5 Flash-Lite", "group": "Gemini 2.5", "input_limit": 1048576}
  ],
  "default_model": "gemini-2.5-flash-lite",
  "default_instruction": "pick up the red cube to the second drawer",
  "available_methods": ["ik_reach_object_v1", "act_gripper_grasp_v1", ...],
  "prompt_template": "You are a robotic task planner..."
}

5.2 POST /api/infer

Run inference: sends image + prompt to Gemini, parses response, saves result.

Content-Type: multipart/form-data

FieldTypeRequiredDescription
modelstringYesGemini model ID (e.g. gemini-2.5-flash-lite)
instructionstringYesNatural language instruction
methodsstringYesComma-separated method IDs
promptstringYesFull prompt text (with instruction + methods already injected)
imagefileYesImage file (JPEG/PNG)

Response (success):

{
  "id": "1717574400_a1b2c3d4",
  "timestamp": 1717574400.123,
  "model": "gemini-2.5-flash-lite",
  "instruction": "pick up the pink bow to the green bowl",
  "methods": ["ik_reach_object_v1", "act_gripper_grasp_v1", ...],
  "prompt": "You are a robotic task planner...",
  "image": "1717574400_a1b2c3d4.jpg",
  "raw_response": "{\"task_id\": ...}",
  "plan": {
    "task_id": "pink_bow_to_green_bowl",
    "total_steps": 4,
    "steps": [
      {
        "step_index": 1,
        "description": "Reach the pink bow",
        "target_bbox": [0.48, 0.47, 0.08, 0.08],
        "method_id": "ik_reach_object_v1"
      }
    ]
  },
  "token_usage": {
    "input": 1234,
    "output": 567,
    "total": 1801,
    "limit": 1048576,
    "remaining": 1047342
  },
  "elapsed": 2.45
}

Response (error):

{"error": "API key not valid.", "elapsed": 0.12}

5.3 GET /api/results

List stored results, newest first.

ParamTypeDefaultDescription

offsetint0Skip first N items

Response:

{
  "total": 42,
  "items": [ { ...result object... }, ... ]

5.4 GET /api/results/{result_id}

Get a single result by ID.

Response: Same structure as a single item from /api/infer.

5.5 DELETE /api/results/{result_id}

Delete a result and its associated image.

Response: {"ok": true} or {"error": "Not found"}

6. Prompt Engineering

The prompt is designed around strict action sequencing rules for a single-arm robot.

6.1 Core Principle

Every act_* step MUST be preceded by ik_reach_object_v1. The robot must reach the target before interacting with it. This is enforced via:

  • Explicit action patterns in the prompt
  • A worked example showing the pattern
  • A closing recap reinforcing the rule

6.2 Action Patterns

TaskStep 1Step 2
Pick up objectik_reach_object_v1 → objectact_gripper_grasp_v1 → object
Place / releaseik_reach_object_v1 → destinationact_gripper_release_v1 → destination
Open drawerik_reach_object_v1 → draweract_drawer_open_v1 → drawer
Close drawerik_reach_object_v1 → draweract_drawer_close_v1 → drawer
Open/close doorik_reach_object_v1 → dooract_door_*_v1 → door

6.3 Container Logic

Container TypeBehavior
CLOSED (drawer, door)Must open BEFORE picking up the object
OPEN (bowl, tray, bin)Pick up object first, then reach container, then release

6.4 Bounding Box Format

YOLO format: [x_center, y_center, width, height], all normalized to [0, 1].

x_center = box_center_x / image_width
y_center = box_center_y / image_height
width    = box_width / image_width
height   = box_height / image_height

7. Robot Methods

Method IDDescriptionPrecondition
ik_reach_object_v1Move arm to target position (IK navigation)None — this IS the precondition
act_gripper_grasp_v1Close gripper to grasp objectMust reach object first
act_gripper_release_v1Open gripper to release held objectMust reach destination first
act_drawer_open_v1Pull drawer openMust reach drawer first
act_drawer_close_v1Push drawer closedMust reach drawer first
act_door_open_v1Open a doorMust reach door first
act_door_close_v1Close a doorMust reach door first

8. Data Storage

Each inference saves two files:

8.1 Image File

Saved to data/images/{timestamp}_{uuid}.{ext}

8.2 Result JSON

Saved to data/results/{timestamp}_{uuid}.json

{
  "id": "1717574400_a1b2c3d4",       // Unique ID (used as filename)
  "timestamp": 1717574400.123,        // Unix timestamp
  "model": "gemini-2.5-flash-lite",   // Model used
  "instruction": "pick up the...",    // User instruction
  "methods": ["ik_reach_object_v1"],  // Methods available
  "prompt": "You are a robotic...",   // Full prompt sent
  "image": "1717574400_a1b2c3d4.jpg", // Image filename
  "raw_response": "...",              // Raw Gemini text output
  "plan": { ... } | null,            // Parsed plan or null
  "token_usage": {
    "input": 1234,
    "output": 567,
    "total": 1801,
    "limit": 1048576,
    "remaining": 1047342
  },
  "elapsed": 2.45                     // API call time in seconds
}

9. Frontend

Single-page app in static/index.html with 3 tabs:

9.1 Tab 0 — Test Gemini API

  • Token Usage: persisted in localStorage, restored on page load
  • Model selector: populated from /api/config
  • Instruction: text input, auto-injected into prompt template
  • Methods: chip-based, add/remove dynamically, auto-injected into prompt
  • Image: required, drag & drop or click to upload
  • Prompt: collapsible, auto-generated, editable for overrides
  • Result: canvas with bounding boxes + step cards + raw response

9.2 Tab 1 — Visualize

  • Grid of all historical results with bbox overlays on thumbnails
  • Filter by model
  • Click to open detail modal (full steps, raw response, prompt)
  • Delete individual results

9.3 Tab 2 — Documents

This page. Full system documentation.

10. Running the Server

10.1 Install Dependencies

pip install -r requirements.txt

Dependencies: fastapi, uvicorn[standard], httpx, pyyaml, python-multipart

10.2 Start Server

python main.py

Or with uvicorn directly:

uvicorn main:app --host 0.0.0.0 --port 8000 --reload

The server runs at http://localhost:8000

10.3 Configuration Changes

Edit config.yaml and refresh the browser. The server reloads the config on every API call — no restart needed.
